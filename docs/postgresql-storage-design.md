# PostgreSQL 문서·세션 저장 설계

- 작업 브랜치: `feat/postgresql-persistence`
- 상태: 저장 계층·API·화면 구현 및 PostgreSQL·Chromium 검증 완료
- 관련 문서: [PostgreSQL 도입 계획](postgresql-implementation-plan.md), [로컬 DB 실행 안내](postgresql-local.md)

## 1. 목표와 범위

서버를 재시작해도 문서·대화·기획 상태를 복원하고, 여러 탭의 편집이 서로 덮어쓰지 않도록 구현한다.

- 로컬 1인 사용, FastAPI 단일 프로세스를 기준으로 한다.
- 최근 문서 목록, 초안 자동 저장, AI 결과 저장, 기존 파일 초안 가져오기를 포함한다.
- 로그인, 과거 버전 조회·복원, Job 이력, Worker, LangGraph 노드 중간 재개는 후속 단계로 둔다.
- 사용자 초안과 AI 생성 결과는 현재처럼 별도로 보존한다.

## 2. 저장 구조

SQLAlchemy 비동기 접근 + psycopg + Alembic을 사용한다. PostgreSQL을 기준 저장소로 삼고 전역 `sessions` 딕셔너리에 의존하는 조회·저장을 제거한다.

| 테이블 | 주요 필드 | 역할 |
|---|---|---|
| `users` | UUID, 고유 개발 사용자 키, 생성 시각 | 고정 개발 사용자 1명. 향후 로그인 연결 기반 |
| `documents` | UUID, 소유자 FK, 제목, 초안 Markdown, Tiptap JSONB, `draft_revision`, 생성·수정 시각 | 사용자가 편집하는 문서 |
| `sessions` | 기존 형식의 세션 ID, 문서 FK·UNIQUE, 상태 JSONB, 상태 스키마 버전, AI 결과 Markdown, 실행 상태, 오류, 실행 토큰, 수정 시각 | 대화와 기획 진행 상태 |

- 이번 단계에서는 문서와 세션을 **1:1**로 생성하며 같은 트랜잭션으로 저장한다. 소유권은 문서를 통해 확인한다.
- 제목은 초안의 첫 비어 있지 않은 줄에서 최대 80자로 추출한다. 초안이 없으면 첫 사용자 입력, 둘 다 없으면 `새 문서`를 사용한다.
- 초안 Markdown과 Tiptap JSON은 같은 트랜잭션에서 저장한다. 편집기 복원에는 JSON, 다운로드에는 Markdown을 사용한다.
- `draft_revision`은 0부터 시작해 저장 성공 시 증가하는 충돌 검사 번호다. 과거 본문 이력을 보관하는 기능은 아니다.
- 대화는 역할·내용·메시지 메타데이터를 보존하는 LangChain 메시지 직렬화 방식으로 저장한다. 상태 전체에 `state_schema_version=1`을 부여하고, 지원하지 않는 버전은 명시적으로 오류 처리한다.
- 지원되는 상태 타입만 명시적으로 직렬화한다. 임의 객체를 문자열로 바꾸거나 pickle로 저장하지 않는다.
- AI 결과는 그래프 호출이 정상 반환했을 때 본문을 확보해 DB에 저장한다. 이후 조회·다운로드는 파일 경로 대신 DB 본문을 사용한다. 이미지·차트 파일은 기존 로컬 저장을 유지하며 DB 백업만으로 복원된다고 간주하지 않는다.

## 3. 저장 흐름과 API·화면

### 초안 저장과 충돌

기존 API 경로와 응답 필드를 유지하면서 다음을 추가한다.

- 세션 응답: `document_id`, `title`, `draft_revision`, `updated_at`.
- `PUT /api/sessions/{id}/draft`: 필수 `base_revision` 추가. DB에서 소유자와 현재 revision을 조건으로 원자적 UPDATE를 수행한다.
- 성공 시 새 revision을 반환한다. revision 불일치는 409, 누락은 422, DB 장애는 503으로 반환한다.
- AI 결과 저장은 초안 필드를 수정하지 않는다. AI 실행 중에도 초안 편집·저장이 가능하다.

브라우저는 기존 1.2초 자동 저장을 유지하고 임시 저장에 기준 revision과 미저장 여부를 함께 기록한다.

- 서버와 같은 revision의 미저장 초안만 자동 저장을 이어간다.
- revision이 다르거나 기준 revision이 없는 기존 브라우저 초안은 자동 전송하지 않는다.
- 충돌 시 편집 내용을 유지하고 자동 저장을 중단한다. **최신본 열기 / 내 편집을 새 사본으로 저장**을 제공한다.
- 최신본을 열기 전 미저장 내용을 별도 복구 캐시에 보존한다.
- 사본은 현재 초안만 복사하고 새 세션으로 시작한다. 이전 대화와 AI 실행 상태는 복사하지 않는다.
- 사본 생성용 `POST /api/sessions/{id}/copy`를 추가해 전달받은 초안과 새 세션을 한 트랜잭션으로 저장한다.

### 문서 목록과 복원

- `GET /api/sessions?limit=20&offset=0`을 추가한다. 최대 limit은 100으로 제한한다.
- 소유한 문서를 수정 시각 내림차순, ID를 보조 정렬 기준으로 조회한다. 목록에는 ID·제목·상태·수정 시각만 반환한다.
- 화면에 최근 문서 목록과 추가 불러오기를 제공한다. 선택하면 DB에서 초안·대화·AI 결과·질문 상태를 복원한다.
- 문서 전환 전에 미저장 내용을 저장하며, 저장 실패나 충돌이 있으면 전환을 중단한다.

### AI 실행과 장애 복구

- 실행 요청을 받을 때 세션을 원자적으로 `running`으로 변경하고 실행 토큰을 저장한 후 백그라운드 작업을 시작한다. 중복 실행은 409로 거절한다.
- 현재 전역 실행 잠금은 유지한다. 모델 호출 중에는 DB 트랜잭션을 열어 두지 않는다.
- 각 그래프 호출이 정상 반환할 때 상태와 AI 결과를 함께 커밋한다. 실패한 호출의 변경은 저장하지 않고 마지막 성공 상태를 유지한다.
- 실행 결과 갱신은 실행 토큰이 일치할 때만 허용한다. 선택 영역 수정도 실행 점유를 공유하지만, 반환한 제안은 사용자가 적용·저장하기 전까지 초안에 반영하지 않는다.
- 서버 시작 시 남아 있는 `running` 세션은 중단 오류로 전환한다. 자동 재실행하지 않고 사용자에게 재요청을 안내한다.
- DB 장애 시 성공 응답이나 메모리 저장으로 대체하지 않는다. 사용자 오류에는 비밀정보를 포함하지 않는다.

## 4. 도입과 기존 데이터

- `DATABASE_URL`을 필수 설정으로 사용하고 연결 풀은 앱 수명주기에 맞춰 관리한다.
- Alembic 초기 마이그레이션으로 테이블·제약·목록 조회 인덱스를 생성한다. 앱 시작 시 자동으로 테이블을 만들지 않고, 연결 및 스키마 준비 상태를 검사한다.
- DB 접근 코드는 저장 계층으로 분리하고 `src/web/app.py`는 요청 검증·서비스 호출·응답 조합을 담당한다.
- 초안의 기존 `.md`·`.json` 이중 쓰기는 중단한다. 다운로드는 DB에서 제공하고 기존 파일은 보존한다.

기존 초안은 명시적 CLI 가져오기로 처리한다.

- 파일 또는 디렉터리 지정과 dry-run을 지원한다.
- 같은 이름의 JSON이 있으면 그 Markdown·Tiptap JSON을 사용하고, JSON이 없을 때만 Markdown 파일을 사용한다. 잘못된 JSON은 보고하고 건너뛴다.
- 기존 세션 ID를 유지해 개발 사용자 소유로 생성한다. 같은 ID가 이미 있으면 덮어쓰지 않고 건너뛴다.
- 과거 대화는 복원하지 않으며 새 초기 대화 상태로 시작한다. 파일별 트랜잭션과 처리 결과 요약을 제공한다.
- 원본 파일은 수정·삭제하지 않는다.

## 5. 검증과 완료 조건

실제 PostgreSQL의 별도 테스트 DB와 모의 모델로 검증한다. 개발 DB에서 테스트 초기화·삭제를 실행하지 않는다.

- 새 세션 생성, 초안 Markdown·JSON·대화·그래프 상태의 저장 및 복원.
- 별도 API 프로세스 재시작 후 같은 세션에서 조회·편집·대화 지속.
- 출력 Markdown 파일 없이도 AI 결과 조회·다운로드 성공.
- 같은 revision으로 두 저장 요청을 보내면 하나만 성공하고 다른 하나는 409.
- AI 실행과 초안 저장이 겹쳐도 초안이 유실되지 않음.
- 모델 오류·DB 오류·강제 종료 후 마지막 저장본 보존 및 중단 상태 표시.
- 브라우저의 오래된 캐시가 최신 DB 내용을 덮어쓰지 않음.
- 충돌 후 최신본 열기·사본 저장, 문서 목록 전환을 데스크톱과 좁은 화면에서 검증.
- 가져오기 재실행 시 중복 없음, 손상된 파일 보고, 원본 보존.
- DB 백업을 별도 DB에 복원한 뒤 문서·세션 내용 확인.

기존 Python 테스트와 브라우저 스모크 테스트를 갱신한다. **재시작 복원·동시 저장 충돌·실패 시 원문 보존이 실제 DB에서 통과하면 이번 단계 완료**로 판단한다.


## 6. 구현 검증 결과

- PostgreSQL 전용 테스트 DB에서 Python 테스트 20개 통과.
- 별도 API 프로세스 강제 종료·재시작 후 초안 Markdown/Tiptap JSON, 대화, 질문 상태, AI 결과 복원 확인.
- 원본 출력 파일이 없어도 DB의 AI 결과 다운로드 가능함을 확인.
- 미완료 실행의 중단 오류 처리, 저장 충돌 409, 사본 저장, 최신본 열기와 복구 캐시 보존 확인.
- 기존 초안 dry-run·중복 방지·손상 파일 처리 및 별도 DB 백업 복원 확인.
- Chromium에서 편집기 스모크 테스트와 데스크톱·390px 모바일 문서 목록 접근 검증 통과.
- 스크린샷: `output/postgresql-storage-desktop.png`, `output/postgresql-storage-mobile.png` (Git 제외).
- 이번 환경에서는 Linux Chromium으로 검증했다. Windows Edge 및 실제 LLM 생성은 이번 검증에 포함하지 않았다.
- 실행 및 테스트 방법은 [로컬 PostgreSQL 안내](postgresql-local.md)를 참고한다.
